## จุดที่สงสัย

- `req.user.id` มาจาก `authenticate` ที่โจทย์ระบุว่าตรวจ token และกำหนดผู้ใช้ให้แล้ว จึงไม่จัดการขอบเขตการตรวจ token ซ้ำใน route; ในโค้ดแก้ยังส่ง ID เป็น SQL parameter เพื่อแยกค่าข้อมูลออกจาก SQL
- Employee กรอง Task ตาม `assigned_to` ในหน้าเว็บ เพราะสเปกระบุว่า `GET /api/tasks` ใช้ได้กับทุกคนที่ Login; โค้ด server ในโจทย์ก็มี filter ผู้รับผิดชอบอยู่แล้ว
- เงื่อนไขเดิม `if (!isAdmin && task.status === 'Done' && status === 'To Do')` เป็นการกัน Employee ย้อนสถานะที่ถูกต้องตามกติกา ไม่ใช่บั๊ก; Admin ต้องข้ามเงื่อนไขนี้ได้
- การใช้ `SELECT ... FOR UPDATE` และ transaction ทำให้ตรวจสิทธิ์/สถานะและเขียน audit เป็นหน่วยเดียว; โค้ดนี้สมมติว่า `db` เป็น PostgreSQL Pool ที่มี `connect()` คืน client ตามรูปแบบ `pg`
